# 12B：MVP 欄位與文案決策

## 1. 文件目的

本文件用來決定 MVP 階段任務建立、任務編輯、任務卡、完成畫面與非 MVP 功能入口的欄位與文案語意。

12B 的重點是：

- 只做產品決策。
- 不改 UI。
- 不改 API。
- 不改 Firestore schema。
- 不實作新功能。
- 後續如果要修改 UI，必須依照本文件拆成小階段處理。

## 2. 建立任務欄位決策

建立任務 modal 的 MVP 欄位策略應以「能建立可追蹤的任務」為核心。任務標題是唯一明確必填欄位，其餘欄位以選填與保守相容為主。

| 欄位 | MVP 定位 | 必填 / 選填 | 12B 決策 | 備註 |
|---|---|---|---|---|
| 任務標題 | MVP 核心欄位 | 必填 | 保留並維持必填 | 建立任務的最低必要資訊。 |
| 任務描述 | MVP 補充欄位 | 選填 | 保留 | 用於描述任務內容，不應阻塞建立流程。 |
| 工單號 / 任務編號 | MVP 可保留欄位 | 選填 | 保留 | 可用於對應外部工單；系統任務 id 不應由使用者手動編輯。 |
| 優先權 | MVP 可保留欄位 | 選填，但可有預設值 | 保留 | 可用於列表排序、篩選與視覺提示。 |
| 狀態 | MVP 系統流程欄位 | 不建議在建立時手動選 | 建立時由系統給預設狀態 | 狀態應由建立、計時、完成、重啟等流程控制。 |
| 到期日 | MVP 可保留欄位 | 選填 | 保留 | 可支援日曆與日期篩選；若有預設值，需確認產品語意。 |
| 負責人 / 指派執行者 | MVP 保守相容欄位 | 選填或預設目前使用者 | 保留但不正式化 members | 不深入 members collection、lineUserId、sourceKey 與權限規則。 |
| 標籤 | MVP 可保留欄位 | 選填 | 保留 | 可支援列表辨識與篩選。 |
| 顏色 | MVP 可保留但非核心 | 選填或預設值 | 保留但不作為核心流程 | 主要作為視覺標識，不應影響任務功能正確性。 |
| 外部連結 URL | MVP 可保留但需後續驗證 | 選填 | 保留，後續補 URL 驗證 | MVP 先避免擴大外部整合。 |
| 備註 | MVP 補充欄位 | 選填 | 保留 | 用於補充處理注意事項。 |
| 子任務 | MVP 可保留資料結構，但建立時不擴大 | 選填 | 12B 不新增建立時子任務流程 | 若目前建立 modal 沒有正式支援，不在 12B 擴大。 |

## 3. 編輯任務欄位決策

編輯任務 modal 應允許使用者修改任務內容欄位，但不應讓一般使用者直接編輯系統欄位、審計欄位或由流程產生的欄位。

| 欄位 | 是否可編輯 | MVP 決策 | 備註 |
|---|---|---|---|
| 標題 | 是 | 可編輯 | 任務主要內容欄位。 |
| 描述 | 是 | 可編輯 | 任務補充內容。 |
| 工單號 / 任務編號 | 是，限外部工單號 | 可編輯 | 系統 id 不可編輯。 |
| 外部連結 URL | 是 | 可編輯，後續補驗證 | URL 格式驗證可拆到後續階段。 |
| 優先權 | 是 | 可編輯 | 影響列表辨識與篩選。 |
| 到期日 | 是 | 可編輯 | 影響日曆與日期篩選。 |
| 標籤 | 是 | 可編輯 | 支援分類與篩選。 |
| 備註 | 是 | 可編輯 | 補充任務處理細節。 |
| 顏色 | 是 | 可編輯 | 視覺標識，非核心流程。 |
| 負責人 / 指派執行者 | 是，保守相容 | 可編輯但不依賴正式 members | 不在 12B 正式化 members。 |
| 狀態 | 不建議作為一般編輯欄位 | 透過完成 / 重啟 / 計時流程改變 | 避免狀態被任意改動造成流程語意混亂。 |
| actualHours | 否 | 不開放一般編輯 | 應由計時器或明確工時流程更新。 |
| history | 否 | 不開放一般編輯 | 應由系統操作自動寫入。 |
| id | 否 | 系統欄位不可編輯 | Firestore document id / 任務唯一識別。 |
| createdAt | 否 | 系統欄位不可編輯 | 建立時間。 |
| updatedAt | 否 | 系統欄位不可編輯 | 更新時間應由系統維護。 |
| sourceKey | 否 | 系統欄位不可編輯 | scope 隔離用欄位。 |
| lineUserId | 否 | 系統欄位不可編輯 | LINE 身份對應欄位。 |

## 4. 任務卡顯示欄位決策

任務列表卡片應優先支援快速掃描與進入詳情，不應承載所有任務細節。

| 顯示資訊 | MVP 顯示定位 | 12B 決策 | 備註 |
|---|---|---|---|
| 任務標題 | 必要顯示 | 必須顯示 | 卡片主內容。 |
| 工單號 / 任務編號 | 輔助顯示 | 有資料則顯示 | 協助對應外部工單。 |
| 狀態 | 必要或輔助顯示 | 必須能辨識 | 可用文字、圖示、樣式或完成標記呈現。 |
| 優先權 | 輔助顯示 | 建議顯示 | 用於快速判斷處理順序。 |
| 負責人 | 輔助顯示 | 可顯示 | 目前保守相容，不代表正式 members 已完成。 |
| 到期日 | 輔助顯示 | 建議顯示 | 支援日期判斷與逾期提示。 |
| 標籤 | 輔助顯示 | 可顯示主要標籤 | 完整標籤可在詳情頁查看。 |
| 計時 / actualHours 摘要 | 詳情頁優先 | 12B 不要求列表顯示 | 若要顯示需另行設計摘要規則。 |
| 顏色標識 | 輔助顯示 | 可保留 | 作為視覺辨識，不應暗示額外狀態。 |

## 5. 任務卡 play icon 行為決策

12B 階段不要讓任務卡 play icon 直接啟動計時。

正式決策：

- 任務卡主行為仍然是進入任務詳情。
- play icon 若保留，應視為「進入執行 / 詳情」的視覺提示。
- play icon 不應在 12B 或 MVP 主線中直接啟動計時。
- 未來若要改成直接啟動計時，必須另開階段。
- 直接啟動計時前，需要處理誤觸、狀態同步、跨裝置一致性，以及是否自動暫停其他任務等問題。

## 6. 完成成功畫面文案決策

如果系統目前沒有真正送出 LINE push、webhook 通知或外部同步，不應宣稱「同步通知已發出」。

MVP 階段的完成成功文案應聚焦於任務本身：

- 任務已完成。
- 任務狀態已更新。
- 已儲存完成狀態。

若要提到同步，只能使用保守文案，例如「任務狀態已更新」。未來若真的支援通知，再另開通知功能階段。

避免使用的文案：

- 同步通知已發出。
- 已通知所有成員。
- 已推播給相關人員。
- 已同步到外部服務。

## 7. 非 MVP 功能入口文案規則

如果非 MVP 功能的 UI 仍存在，文案必須避免讓使用者以為功能已正式完成。

適用功能：

- Chat AI。
- Dashboard。
- Google Sheets 同步。
- 推播通知。
- 外觀設定。
- LINE 隱私設定。
- 頭像編輯。
- 群組切換。

文案規則：

- 可以保留 UI，但要避免讓使用者以為已正式完成。
- 可標示為「暫未啟用」、「Demo」、「未來版本」、「開發中」。
- 不要使用會暗示已經可用的文案。
- 若入口會干擾 MVP，後續可另開 12F 處理入口整理。

## 8. 12B 結論

12B 不實作功能，只鎖定欄位與文案語意。

MVP 欄位策略是：

- 任務標題必填。
- 其他欄位以選填與保守相容為主。
- members / 指派欄位不在 12B 正式化。
- 系統欄位不可編輯。
- 任務卡不直接啟動計時。
- 完成文案不可宣稱尚未實作的通知或同步能力。
